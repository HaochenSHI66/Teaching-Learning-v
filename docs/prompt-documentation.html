系统架构总览

PPT 上传后经历以下流水线处理，最终生成逐页讲解、对话、笔记、测验等功能。

上传 PPT
→
PyMuPDF 提取文本
→
后端预检测
标题 / 目录 → Compact
→
LLM 二次判定
<!-- page_type -->
→
按类型分支输出
→
清洗 & 写入 DB

三种 Pipeline 路径

  1. Compact-Static（无 LLM）：后端预检测为标题页/目录页时直接本地生成 Markdown
  2. Dual Pipeline（双模型）：视觉模型读图提取 → 文本模型生成讲解（推荐）
  3. Single Pipeline（单模型）：视觉模型直接读图生成讲解（Dual 不可用时回退）

页面类型判定的双层机制

  • 第一层：后端规则预检测（_detect_compact_slide_type()）— 基于词数、块数等硬规则，命中则跳过 LLM
  • 第二层：LLM Prompt 内判定（<!-- page_type: ... -->）— 模型看图后自行判断，结果写入 meta.content_type
  • 两层结果冲突时以 LLM 判定为准（LLM 能看到图片，信息更丰富）

调用场景
单视觉模型看图生成讲解

最核心的 Prompt。视觉模型直接看 PPT 截图后生成逐页讲解。采用五步式结构：判断页面类型 → 判断页面角色 → 按视觉阅读顺序 → 解释关系而非复述 → 按类型输出。

PROMPT TEMPLATE你是一个中文大学课程助教。请讲解当前这页PPT。 第一步：判断页面类型 先根据当前页内容判断它属于哪种类型，在输出开头用一行标注： <!-- page_type: title / toc / intro / content / example / summary --> - 标题页（title）：只有课程名、章节名、讲师信息等，几乎无实质内容 - 目录页（toc）：列出章节大纲、议程、提纲、outline - 导入页（intro）：章节开头的引言、背景、动机、问题引入 - 讲解页（content）：有正文、概念、公式、图表等实质教学内容 - 例题页（example）：讲解页中包含例题、习题、worked example、solution、求解、解答 - 总结页（summary）：章节末尾的回顾、要点汇总、take-away 第二步：判断当前页在本章中的角色 判断当前页在做什么：引入问题？定义概念？对比方案？推导公式？演示例子？总结回顾？ 这决定你用什么方式讲——引入就设问，定义就划重点，对比就列表，推导就逐步。 第三步：按视觉阅读顺序 先讲解当前页上最醒目的视觉元素（大标题、图表、公式、高亮框）。 然后按阅读顺序讲解其余内容。不要机械按 bullet 顺序平铺。 第四步：解释关系，不要只是复述 讲清楚前后知识点的关系：前提是什么、解决什么问题、为什么 A 导致 B。 不要把 PPT 上的文字换个说法重新写一遍。 第五步：按类型输出 【标题页】只输出： ## [当前页原始标题] 用 1 句话说明这是哪门课/哪个章节的起始页。（60-100 字） 【目录页】只输出： ## [当前页原始标题] 按原页顺序列出各条目，不展开解释。（60-100 字） 【导入页】只输出： ## [当前页原始标题] 用 1-2 句话说明本章要解决什么问题或引出什么背景。（80-160 字） 【讲解页（无例题）】输出： ## [当前页原始标题] ### 这页讲什么 用 1-2 句话直接说清这页的核心。必要时可对最核心的问题句或结论句使用 <mark>...</mark> ### 逐点讲解 - 点 1：…… - 点 2：…… （按当前页实际内容条数来，不要凑数也不要遗漏） ### 本页关键结论 - 最该记住的 1-3 条结论 如确有必要，可在最后补充 1 个 callout（放最后，不要插到正文中间） （150-230 字，图表/公式页 220-320 字） 【例题页】输出： ## [当前页原始标题] ### 这页讲什么 用 1-2 句话说明这是什么类型的例题、考察什么知识点。 ### 题目分析 列出题目的已知条件和求解目标。 ### 解题过程 按步骤讲解，每步说清用了什么公式/定理、为什么这样做。公式用 KaTeX。 ### 本页关键结论 - 这道题的核心方法和易错点 （220-320 字） 【总结页】只输出： ## [当前页原始标题] 按原页结构列出要点，不重新展开。（80-160 字） 硬性要求： 1. 只根据当前页可见内容讲解，不脑补看不到的内容。 2. 优先解释当前页最醒目的信息（大标题、图、表、高亮框），再按阅读顺序展开。 3. 必要时说明为什么重要；如果一个点本身显而易见，就不要额外展开"重要性"。 4. 不要加入考试技巧、记忆口诀、题外类比，除非当前页本身很抽象且不用类比讲不清。 5. 不要输出"知识点摘要""本页概念"这类固定模板块。 6. 不要重复上一页已经讲过的大段内容；如果和上一页重复，只指出本页新增点。前序页摘要只用于避免重复，不要显式写出"上一页/前面提到过"，除非当前页本身就在做对比。 7. 用简单直接的中文，像助教在旁边给学生解释，不要写成营销文案。 8. callout 受控开放：确实需要时可在页面最后放 1 个 callout（NOTE / TIP / WARNING），不要插到正文中间。 9. 必须使用中文，核心术语保留英文括注。 10. 不要写成报告体（"本页介绍了…""本节讨论了…"），直接讲知识本身。 11. 不要把 PPT 文字换个说法重新写一遍（paraphrase），要解释为什么、怎么来的、有什么用。 12. 如果当前页有问题句（设问、反问），必须用 <mark> 高亮并回答它。 标题规则： - ## 标题优先使用当前页 PPT 原始标题（英文也可以） - 如果原始标题过短（≤2 词）或过泛（如"Introduction"），再补一个不超过 8 个字的中文主题 术语和格式： - 术语用 **加粗**：**中文 (English)**。首次出现标英文，同页后续可只写中文；跨页首次再补英文 - 公式用 KaTeX：$...$ $$...$$ - PPT有分点就保留分点结构，有流程就用箭头 → 描述 - 不要用反引号 ` 包裹普通文本 - 不要输出课程号、讲师名、页码 强调与版式规则（三级层次）： - **加粗**：关键术语、对比项、关键机制，每页 4-8 处 - <mark>...</mark>：核心问题句、定义、结论，每页最多 2 处 - Callout：每页最多 1 个，放在最后，只限 NOTE / TIP / WARNING 页码：{page_num} 相关页码：{related} 问题：{question} 提取文本： {extracted_text}

引擎逻辑

页面类型检测（双层机制）

页面类型通过两层机制判定：后端规则预检测 + LLM Prompt 内判定。

第一层：后端规则预检测 — _detect_compact_slide_type()

返回 "title" / "toc" / None。命中 title/toc 时不调用 LLM，直接本地生成。

检测流程

  1. 有密集内容？（公式/代码/表格）→ 返回 None
  2. 目录关键词命中？ → 返回 "toc"
  3. 标题页条件：总词数 ≤ 6、标题行 ≤ 4 词、文本块 ≤ 2、无 bullet、图片 ≤ 1、无标点 → 返回 "title"
  4. 否则 → None，进入 LLM 讲解流程

第二层：LLM Prompt 内判定 — <!-- page_type: ... -->

当后端未预判为 compact 时，LLM 在 Prompt 指导下自行判定页面类型（6 种：title / toc / intro / content / example / summary），输出在首行以 HTML 注释标注。_PAGE_TYPE_COMMENT_RE 正则匹配所有 6 种类型。

后端解析流程（explanation_engine.py）

  1. _extract_llm_page_type(markdown) 用正则从 LLM 输出中提取 page_type
  2. _strip_disallowed_sections() 清洗时自动移除该注释（不会出现在前端）
  3. _canonicalize_slide_explanation() 将 LLM 的 page_type 写入 meta.content_type
  4. 如果 LLM 判定为 example，强制设置 is_example = True

例题页检测（双层机制）

例题页也通过两层判定：后端关键词匹配 + LLM page_type 判定。

后端关键词匹配 — _looks_like_example_page()

example worked example exercise solution solve problem 例题 题目 解答 求解

检索范围：提取文本、用户问题、payload 的 summary 和 title_candidates。

LLM 判定 — <!-- page_type: example -->

如果 LLM 输出了 <!-- page_type: example -->，后端强制设置 is_example = True，即使后端关键词未命中。

例题页对讲解输出的影响

  • content_type 标记为 "example"
  • 解析 LLM 输出中的 ### 题目分析 和 ### 解题过程（v5 新增）
  • 同时兼容旧格式：### 例题讲解 / ### 例题完整讲解 / ### 例题解析 / ### 习题讲解
  • 题目分析 + 解题过程自动合并为 primary_md

重复分析 & 上下文注入

PPT 相邻页常有重复内容。系统通过 repeat_analysis 检测重复并注入 Prompt。

自动追加到 extracted_text 末尾 重复分析： - 最近比较页：3, 4, 5 - 检测到重复页：4 - 重复占比：0.35 - 新增块数量：3 - 重复块摘要： - 当前块 b2 与第 4 页重复：Memory is divided into fixed-size frames...

重复判定条件

has_repeat_section = True 当且仅当：存在重复页 且（重复占比 ≥ 0.30 或 重复块数 ≥ 2）

v5 变更：第 7 条从"如果相邻页内容重复，合并或只记新增部分"改为"保持逐页结构不变，每页必须有自己的 ## 节"。
原因：用户看第 8 页时期望笔记也在第 8 页，合并会破坏页面一一对应关系。

笔记逻辑

笔记 Fallback（无 LLM 回退）

当 LLM 不可用时，build_notebook_fallback() 用纯规则从讲解文本中提取笔记。v5 重写了提取策略。

v5 提取策略（优先级从高到低）

  1. 提取 "### 本页关键结论" 中的 bullet（新增）— 这是讲解中已经最压缩的部分，最多取 2 条
  2. 提取 <mark> 高亮 — 讲解中已标注的核心内容，最多补到 3 条
  3. 术语句子填充 — 含双语术语模式（中文 (English)）的句子优先
  4. 每条经过 _compress_sentence() 压缩（新增）— 按语义断句取第一子句，目标 ≤60 字
v5 变更：
旧版只是从讲解中摘句子（_sentence_candidates → 评分 → 截断），本质是"摘抄"。
新版优先从"### 本页关键结论"提取（已是最精简内容），并用 _compress_sentence() 按语义分句压缩（在逗号/分号处切分取第一子句），而非硬截断加省略号。

_compress_sentence() 压缩逻辑

  1. ≤60 字 → 原样返回
  2. 尝试在"，即"/"，也就是"/"，因此"/"，所以"/"；"/"，但"处分割，取前半
  3. 仍超长 → 在 60 字内找最后一个逗号/句号处切断
  4. 都失败 → 硬截断 + "…"

引擎逻辑

输出清洗 & 后处理

sanitize_slide_markdown() 清洗流程

  1. 占位标题替换（"Slide 标题" → 真实标题）
  2. 缺失标题补充
  3. 删除禁止 section（自测/Quiz）
  4. Callout 保留首个，剥离多余（v6：_keep_first_callout()，见下方说明）
  5. 剥离 <!-- page_type: ... --> 注释（v5 新增）
  6. AI Filler 过滤（短行 ≤40 字时移除）
  7. 课程信息/页面描述过滤
  8. 反引号清理、Bold 格式修复、空行压缩
v6 变更：第 4 步从"删除 NOTE callout"（_NOTE_CALLOUT_RE 移除所有 NOTE/TIP/WARNING）改为 _keep_first_callout()：
- 正则名从 _NOTE_CALLOUT_RE 改为 _CALLOUT_RE，匹配 NOTE / TIP / WARNING 三种
- 保留第一个匹配到的 callout，剥离其余多余 callout
- 配合 Prompt 端"受控开放"策略：允许模型输出最多 1 个 callout，后处理兜底确保不超

_canonicalize_slide_explanation() 结构化规范

  • translation_md — 主讲解内容
  • primary_md — 例题讲解（题目分析+解题过程合并）或知识点总结
  • repeat_md — 重复部分讲解
  • summary_md — 知识点摘要
  • concepts — 提取的概念列表

Section 匹配支持：精确匹配 → 归一化匹配 → 别名表 → 子串包含 → difflib fuzzy ratio ≥ 0.7
